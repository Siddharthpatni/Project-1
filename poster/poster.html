Self-Improving LLM Agents for Automated Web-Scraper Generation in Public Procurement

Maxi1 · Marwin1 · Fabian1 · Radu2 · Victor2 · Siddharth Patni1 · Prakshal1 · Dhruvin1 · Utsav1   Project leads: Prof. Dr. Christian Bartelt1 · Kristian Kolthoff1
1TU Clausthal · CORE · CICONIA Systems    2Universitatea Babeș-Bolyai  ·  DIGIT Review Party #3, GoTec II, Goslar, 3 July 2026

Abstract

Collecting public tender documents requires a bespoke web scraper for each of hundreds of incompatible e-procurement portals — a manual process that does not scale. We present Vergabepilot.AI, a system in which a large language model synthesises a Python scraper per domain inside a closed generate–validate–execute–evaluate loop that iteratively repairs its own code, complemented by a visual computer-use agent and a cost-aware cascade that reuses cached scrapers before invoking any model. On a benchmark of 100 URLs spanning 30+ portal types, the system retrieved documents for 97% of URLs at a total LLM cost of $0.02; across 10 evaluated models the smallest and cheapest model matched the largest, indicating that model scale is not the limiting factor for this task.

1

Introduction

Public procurement notices (Vergabe) are published across hundreds of heterogeneous portals (DTVP, NetServer, Cosinex, RIB iTWO, Subreport, …), each with a distinct layout, access wall and document structure. Conventional practice builds and maintains a separate scraper per source; the engineering effort grows with the number of domains and becomes the dominant cost.

Contributions.

  • A closed-loop agent system that synthesises and self-repairs domain-specific scrapers via static-safety-checked, sandboxed execution.
  • A cost-aware cascade with a visual computer-use fallback that minimises LLM expenditure.
  • An empirical study over 100 URLs, 30+ portals and 10 LLMs, achieving 97% retrieval at $0.02.

Experimental Setup

  • Dataset: 100 public German tender URLs spanning 30+ portal types (NetServer, DTVP, Cosinex/eVergabe 4.9, RIB, Subreport, TYPO3, SharePoint, Ariba, …), auto-classified before any network call.
  • Models: 10 LLMs evaluated (Gemini 2.5 Flash Lite/Flash/Pro, GPT-4o mini, GPT-4.1(/mini), Claude Sonnet/Haiku, DeepSeek V3).
  • Metric: retrieval success — correct tender documents obtained per URL, judged by the Evaluator against expected outcomes.
  • Infrastructure: FastAPI · Celery (4 workers) · Redis · sandboxed execution · MinIO · PostgreSQL.

Discussion

  • Caching dominates cost: only 4 of 79 model calls were new (75 cached), so cost scales with the number of new domains, not URLs.
  • Scale ≠ quality: the smallest model (Gemini 2.5 Flash Lite) matched the largest; pricier models added latency and cost without higher success.
  • Graceful limits: authentication walls and CAPTCHAs are detected and routed to the CUA agent or flagged for manual action rather than failing silently.
8

Conclusion & Future Work

A self-refining generate-and-verify loop combined with a cost-aware cascade turns fragmented procurement portals into reliable, near-zero-cost document discovery. Future work: vision-capable computer-use models, automated regression detection when portals change, and extension beyond Germany to additional jurisdictions.
